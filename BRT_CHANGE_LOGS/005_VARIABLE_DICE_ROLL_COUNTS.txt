BEFORE

12-word dice generation always stopped at 99 rolls.
24-word dice generation always stopped at 198 rolls.
The roll buffer held only 200 values.
The user could not select a larger roll count.
The seed word count was inferred by comparing the target to 198.
Entropy extraction could be called before the selected target was complete.
The dice test only checked that one hash was not all zeroes.

AFTER

12-word dice generation requires at least 100 rolls.
24-word dice generation requires at least 200 rolls.
The user can select any target from the applicable minimum through 500.
The selector provides -10, -1, +1, and +10 controls and a START button.
The collector buffer safely holds exactly 500 rolls.
Targets below the applicable minimum or above 500 are rejected by the collector.
Values outside 1 through 6 are rejected.
A 501st roll is rejected without changing the completed 500-roll collection.
The storage function independently checks the physical 500-roll buffer limit even if its target is corrupted.
The touchscreen checks whether every roll was accepted and shows a visible error instead of silently continuing.
The collector records whether it is producing 12 or 24 words; the code no longer guesses from the target.
Entropy extraction refuses to produce output until the selected target is complete.
Failure is logged, shown on screen, and returned to the dice setup flow instead of silently continuing.

ENTROPY PROCESS

Each accepted die value is stored as one byte with a value from 1 through 6.
Only the exact number of rolls selected by the user is hashed.
For 12 words, SHA-256 is calculated over the rolls and the first 16 bytes become the 128-bit BIP39 entropy.
For 24 words, two domain-separated SHA-256 calculations are made and 16 bytes from each are combined into 32 bytes of BIP39 entropy.
Increasing the target does not slow the device in a meaningful way. Hashing 500 bytes is small for the ESP32-S3.
